# Android 业务交付说明

业务 UI 通过共享 UniFFI Client 访问配置和 Xboard API，使用 Compose 原生页面；付款二维码由本地 ZXing 渲染。客户端由 `Client.forDeployment` 构造，界面不接受任意机场地址或 Chatwoot 管理令牌。

## 页面与行为

- 底栏为总览、节点、订阅、客服、我的。订阅/客服受功能开关控制，历史订单、自定义分流和功能偏好位于“我的”。首页保留快捷入口。
- 账户支持礼品卡核验、奖励预览、明确确认后兑换、最近兑换记录；盲盒明确标注随机发放。邀请支持统计、生成、复制。
- 自定义规则支持新增、编辑、启停、上移、删除；由共享 core 验证并按账户隔离存储，下次连接时应用。
- 功能偏好只允许在服务方开放的范围内隐藏功能，无法重新开启被服务方关闭的能力。配置未加载时不开放写入口；已有订单始终可访问。
- 原生 Chatwoot 支持会话恢复/选择、发送消息、附件链接、前台每 10 秒刷新、未读计数和应用内提醒。未配置时说明原因并提供工单入口。source_id 等公共凭据留在 core/安全存储，不传入 Compose。
- 新购先创建订单并读取服务端详情，再展示余额/优惠/手续费和实付金额，用户确认后才调用 checkout。周期验券使用新 FFI 参数；0 元订单无需支付渠道。未知创建结果引导用户检查历史订单，不自动重建或取消。
- 新购与历史待付款共用 `OrderPaymentSheet`，保留已绑定支付渠道和手续费，支持本地二维码/浏览器付款/复制信息，支付回流仅查询真实状态。状态 1 显示正在开通，3/4 才完成；单次轮询约 10 分钟，关闭面板取消轮询。
- 登录、注册、找回密码和发送邮箱码接入动态 Turnstile/reCAPTCHA v2/v3。v3 按具体操作执行，token 只保留内存并消费一次。WebView 使用站点 HTTPS origin、默认 UA 与 DOMStorage，限制官方挑战资源，禁文件和任意主页面跳转；不暴露 JavaScript native interface。
- 启动恢复会话后通过 checkLogin 确认有效性；临时网络错误保留已恢复会话，明确 Unauthorized 会立即清除用户界面。所有用户/订阅/节点/套餐/订单/工单响应按会话和请求版本校验，退出后不回填旧数据。清理任务等待在途连接结束后断开；新登录和连接等待该任务结束。公开站点配置保留以便继续验证登录。

## 验证

业务 UI 与新 FFI、付款面板与 ZXing、动态验证码接线、最终会话修复已连续四轮通过 `compileDebugKotlin`（最终会话版 1 分 22 秒，exit 0，无 Kotlin 警告）。构建副本已核对下列四个冻结源码指纹一致；最终 APK 与三 ABI 原生库以 Android 打包日志为准。

`node android/tests/captcha-widget.mjs` 从 Kotlin 源码读取真实验证码 HTML/JS 片段，在隔离浏览器中验证显式 render、v3 按操作 execute、结果/重置回调及 CSP。仅官方脚本响应在测试边界被替换，生产没有测试开关。
