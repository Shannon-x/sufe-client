# update-server

Static manifests served from the project's `gh-pages` branch (i.e.
`https://shannon-x.github.io/sufe-client/...`). Two consumers:

- **Tauri desktop updater** — polls `desktop/latest.json`. Shape per
  [Tauri 2 updater plugin docs](https://tauri.app/plugin/updater/).
- **Android distribution metadata** — `mobile/android/latest.json` records the signed APK hash and URL. The current Android client does not poll or install from this manifest.

Release manifests are generated by CI from signed release artifacts; this directory currently contains documentation, not production manifests. Desktop and Android publishing jobs update their own paths on `gh-pages` after a release is published. The optional `dist/` landing content is copied only when provided.

## Published URL layout

After CI publishes for the first time:

```
https://shannon-x.github.io/sufe-client/
├── index.html                       # optional landing page, if supplied
├── desktop/latest.json              # Tauri updater (4 platforms)
└── mobile/
    └── android/latest.json          # APK manifest
```

iOS has no manifest or automated distribution in this workflow; signing and TestFlight/App Store distribution require separate operator setup.

## Tauri desktop manifest

```json
{
  "version": "0.2.0",
  "notes": "Tag v0.2.0",
  "pub_date": "2026-09-27T12:00:00Z",
  "platforms": {
    "darwin-aarch64":   { "url": "...", "signature": "..." },
    "darwin-x86_64":    { "url": "...", "signature": "..." },
    "linux-x86_64":     { "url": "...", "signature": "..." },
    "windows-x86_64":   { "url": "...", "signature": "..." }
  }
}
```

`signature` is the ed25519 detached signature emitted by
`tauri-action`; the public key sits in `desktop/src-tauri/tauri.conf.json`
under `plugins.updater.pubkey`. CI imports the matching private key
from the repo secret `TAURI_SIGNING_PRIVATE_KEY`.

To wire the Tauri updater, set this URL in
`desktop/src-tauri/tauri.conf.json`:

```json
"plugins": {
  "updater": {
    "endpoints": [
      "https://shannon-x.github.io/sufe-client/desktop/latest.json",
      "https://github.com/Shannon-x/sufe-client/releases/latest/download/latest.json"
    ],
    "pubkey": "..."
  }
}
```

The second endpoint is a fallback in case gh-pages is briefly stale —
Tauri tries them in order and uses the first one that returns a
manifest with a higher `version`.

## Android manifest

```json
{
  "version": "0.2.0",
  "url": "https://github.com/.../xboard-v0.2.0-android.apk",
  "sha256": "deadbeef...",
  "min_version": "0.1.0",
  "force": false,
  "notes": "Tag v0.2.0"
}
```

This file is release metadata only. Android startup polling, download verification UI, installation and forced-update behavior are not implemented. The example fields do not enable those capabilities. Signed APKs are published only when the Android signing configuration and native ABI checks pass.

## Local smoke test

```sh
# Render a sample manifest from a fixture release
GITHUB_REPOSITORY=owner/repo \
GH_TOKEN="$(gh auth token)" \
ci/scripts/build-desktop-manifest.sh v0.2.0 /tmp/latest.json

# Validate JSON
jq . /tmp/latest.json
```
